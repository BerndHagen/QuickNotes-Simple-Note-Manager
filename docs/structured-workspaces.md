# Structured workspace architecture and product matrix

QuickNotes currently supports ten canonical workspace types. Document, Paper, and Canvas use their own content engines. The seven structured workspaces below persist versioned `noteData` on the same note catalog record, participate in the shared lexical search projection, use the common inspector and note identity, and are covered by the normal note sync, version, template, export, backup, and restore paths. A specialized editor is a view of that canonical record; it must not create a second note, task, reminder, tag, or resource identity.

## Shared redesign rules

- The workspace header is a compact title and context row. Its icon is a semantic glyph, not a decorative colored tile.
- Summaries are plain secondary metadata separated by rules. Empty or zero-value statistics do not become promotional cards.
- Primary input comes before filtering and advanced attributes. Enter submits wherever the workflow is naturally repetitive.
- Working regions are flat, bounded by separators, and use the full useful width. Cards are reserved for movable or independently actionable objects.
- Destructive and secondary actions remain contextual but keyboard and touch reachable.
- At phone widths, navigation and metadata must never permanently squeeze the primary activity. Horizontal scrolling is limited to deliberate tabs, boards, and compact command strips.
- Existing `noteData`, stable IDs, task-source locators, resource IDs, reminder links, search projection, sync and backup contracts remain unchanged by the UI pass.
