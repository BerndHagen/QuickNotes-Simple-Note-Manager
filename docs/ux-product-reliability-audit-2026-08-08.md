# QuickNotes UX, product, and reliability audit

Date: 2026-08-08

Scope: the 32 observations in the requested focused review

Severity: high = data, access, or core-workflow trust; medium = recurring task friction or accessibility; low = polish or an edge condition.

## Method and verification boundary

The implementation, existing Supabase migrations, RLS policies, RPCs, relationships, offline queue, and automated tests were inspected before changes were selected. Browser verification used production assets in Chromium and mobile WebKit, including 320–1920 px widths, phone landscape, short/keyboard-like viewports, light and dark themes, keyboard paths, focus/scroll locking, and axe WCAG A/AA scans.

The environment did not expose the stated Supabase MCP connection, Supabase CLI, PostgreSQL client, or Docker. Consequently, the real remote project's data and applied-migration state could not be queried and the new SQL migration could not be executed remotely in this session. The checked-in schema was reviewed and a forward-only migration was prepared; it must be applied by the normal Supabase deployment pipeline before the new RPC and RLS behavior is live. The frontend retains a privacy-safe compatibility path until that occurs.

## Supabase migration review

`20260808190000_shared_note_provenance_and_trash_privacy.sql` is forward-only and preserves existing rows:

- Replaces only the notes SELECT policy so owners retain Trash access while collaborator reads require `not deleted`.
- Adds active-note guards to new invitations and accepted grants.
- Hardens the shared-note update RPC against trashed notes.
- Filters pending and accepted RPC results to active notes.
- Adds a privacy-safe accepted-share RPC with owner display name/ID but no email or avatar URL.
- Uses existing primary keys and `accepted_shares(user_id)` indexing; no data rewrite or destructive table change is performed.

Hard deletion remains deliberately cascading through `shared_notes`, `accepted_shares`, and `note_versions`. Soft deletion retains related rows during the 30-day Trash window so restoring the note restores the prior collaboration relationship. No attachment table exists in the checked-in schema.
