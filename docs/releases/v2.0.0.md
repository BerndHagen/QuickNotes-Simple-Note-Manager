QuickNotes `2.0.0` is a security and data-integrity milestone. It moves collaboration rules into the database, isolates every account's local and cloud records, introduces complete password recovery, and hardens content handling across editing, import, preview, history, and export workflows.

### Collaboration Security

- **Server-enforced sharing**: invitations, acceptance, decline, revocation, and collaborator edits run through audited database routines rather than trusting client-side state.
- **Access must originate from a real invitation**: accepted collaboration is tied to an invitation, and revoking that share removes the collaborator's access.
- **Narrow collaborator permissions**: collaborators can change note title, content, note type, and structured data when permitted; ownership, organization, sharing, and destructive controls remain owner-only.
- **No anonymous database access**: version history, invitations, accepted shares, and account data are protected from unsigned clients.

### Tenant and Data Integrity

- **Account boundaries at every layer**: local caches are owner-scoped and cloud relationships use tenant-scoped foreign keys, preventing cross-account references even when an identifier is known.
- **No autosave-window data loss**: pending editor content is committed before reload or navigation can discard it.
- **Stable folder synchronization**: identical folder names in local and cloud data no longer break note-folder reconciliation.
- **Collaboration without upload loops**: incoming shared changes do not re-enter the outgoing queue and overwrite another editor's work.

### Account and Content Safety

- **Complete password recovery**: account recovery includes a dedicated flow and a stronger 12-character minimum password policy.
- **Sanitized rich content**: HTML is cleaned consistently during import, preview, version-history display, quick-note handling, and PDF generation.
- **Shared validation rules**: note titles, folders, and tags follow the same constraints in the interface and database.
- **Complete account deletion**: deleting an account removes its related notes, versions, invitations, grants, folders, and tags through defined database relationships.

### Workflow Reliability

- **Recurring reminders recur**: daily, weekly, and monthly reminders reschedule after firing instead of silently becoming one-time alerts.
- **View-only means read-only**: specialized task, project, meeting, journal, brainstorm, shopping, and weekly workspaces respect shared-note permission level.
- **Accessible confirmations**: browser alerts and confirmations were replaced with keyboard-operable QuickNotes dialogs that trap and restore focus.
- **Consistent dates and sorting**: dates, times, numbers, and ordering use one predictable locale baseline throughout the application.

### Reproducibility and Quality

- **Versioned database migrations**: supported schema changes are stored under `supabase/migrations` so the cloud model can be reviewed and reproduced.
- **Broader regression coverage**: validation, sanitization, reminders, synchronization, responsive behavior from phone to ultrawide, and WCAG A/AA workflows are exercised before release.
- **No repository test credentials**: end-to-end account credentials come from the environment rather than a hardcoded user.
